> Git 의 어려운 개념을 "저장 · 올리기 · 받아오기 · 되돌리기" 같은 쉬운 말과 화면으로 바꾼 데스크톱 앱

## 1. 왜 만들었나

Git 은 개발의 필수 도구지만 처음 쓰는 사람에게는 `commit`, `push`, `merge`, `conflict` 같은 개념 자체가 진입 장벽입니다.
GitHub Desktop, Sourcetree, GitKraken 같은 GUI 도 있지만 대부분 **Git 을 이미 아는 사람**이 편하게 쓰도록 설계되어 있습니다.

최근에는 AI 코딩 도구로 개발 경험 없이 프로그램을 만드는 사람이 늘었습니다. 이들은

- AI 가 코드를 망가뜨렸을 때 **잘 되던 상태로 돌아가는 방법**을 모르고
- API 키가 든 `.env` 를 **실수로 GitHub 에 올리기 쉽고**
- 팀원과 같은 파일을 고쳤을 때 나타나는 `<<<<<<<` `>>>>>>>` **충돌 표시 앞에서 막힙니다.**

그래서 목표를 **"Git 을 쉽게 쓰는 도구"가 아니라 "Git 을 몰라도 안전하게 저장하고 협업할 수 있는 도구"** 로 잡았습니다.

## 2. 주요 기능

### 쉬운 말로 바꾼 Git
- 화면의 모든 용어를 쉬운 말로 쓰고 Git 용어를 작게 함께 표시 (예: 저장 지점 `commit`, 올리기 `push`) — 마우스를 올리면 뜻을 설명
- 시작 화면: 내 프로젝트 열기 / 새로 시작하기(Git 시작 + 기본 `.gitignore`) / GitHub 에서 가져오기 / 데모 둘러보기 / 최근 저장소
- 이름·이메일이 설정 안 된 경우 첫 커밋 전에 안내하고 앱에서 바로 설정

### 저장(커밋)과 안전장치
- 바뀐 파일을 체크해서 원하는 것만 커밋 (미리 stage 된 다른 파일이 섞이지 않음)
- **비밀 정보 보호**: `.env`, 개인 키, `credentials.json` 등은 기본으로 제외하고, 포함하려 하면 경고 / 올리기 전에도 한 번 더 확인
- **무시 목록 도우미**: `node_modules`, 빌드 결과물, 로그 파일을 묶어 보여주고 `.gitignore` 에 한 번에 추가
- **큰 파일 경고**: 50MB 이상 경고, 100MB 초과는 GitHub 이 받지 않는다고 안내
- **diff 보기**: 바뀐 줄을 나란히 / 한 줄로 보기

### 올리기·받아오기·충돌 해결
- 올리기: 모두 올리기 / 특정 저장 지점까지 올리기, 처음 올리는 갈래는 온라인에 만들고 연결
- 받아오기: 받기 전에 누가 무엇을 올렸는지 미리보기, 내 쪽 변경이 없으면 fast-forward, 양쪽 다 있으면 merge
- **충돌 시 자동 취소 후 원래 상태로 복구** → 원하면 **충돌 해결 화면**:
  `<<<<<<<` `=======` `>>>>>>>` 대신 "내 것 / 온라인 것" 카드를 나란히 보여주고 버튼으로 선택. 기호가 남은 채 저장하는 실수를 막음
- GitHub 연결: 빈 저장소 만드는 법 안내 → 주소 붙여넣기 → 연결하고 첫 올리기 (로그인은 Git Credential Manager)

### 되돌리기와 시간 기록
- 그래프에서 저장 지점을 골라 그 상태로 되돌리기 — **기록을 지우지 않고** 되돌린 상태를 새 저장 지점으로 쌓아 온라인에 올린 기록도 안전
- 되돌리기 전 저장 안 한 변경은 자동 백업, 언제든 되살리기
- 커밋 직후 되돌리기 = "방금 저장한 것 되돌리기"
- **시간 기록(스냅샷)**: 커밋하지 않아도 그 순간을 찍어 두고 나중에 돌아가기 — 저장 기록과 GitHub 에는 나타나지 않음

### 저장 기록 그래프
- GitKraken 스타일 그래프: 갈래별 색 레인, 갈라짐·합침 곡선, 갈래·태그·온라인 위치 라벨
- 점에 마우스를 올리면 요약 카드: "여기서 ‘실험/갤러리’ 갈래의 저장 지점 2개를 합쳤어요", "main 의 5번째 저장 지점", 바뀐 파일과 줄 수

### 웹 데모와 사용자 테스트
- 같은 화면을 가짜 데이터로 움직이는 데모 모드를 GitHub Pages 로 배포 — 저장·올리기 / 되돌리기 / 팀원과 충돌 세 가지 과제
- 과제별 소요 시간과 선택(비밀 파일을 뺐는지 등)을 기록해 사용성 테스트에 활용

### AI 도우미 (서버 완성, 앱에서는 준비 중으로 비활성화)
- 바뀐 내용을 쉬운 말로 설명, 저장 메시지 추천(저장소의 최근 메시지 말투에 맞춤), 충돌 설명과 추천 선택
- 기능 스위치 하나(`AI_ENABLED`)로 켜고 끄도록 설계

## 4. 구현에서 신경 쓴 점

### 4.1 사용자 코드를 절대 망가뜨리지 않기
- **되돌리기는 `git reset` 대신 "그 상태의 새 저장 지점"** 을 만드는 방식 — 기록이 사라지지 않고, 이미 올린 기록도 안전하게 되돌림
- **저장 안 한 변경 백업**: 임시 index 파일(`GIT_INDEX_FILE`)로 저장 지점을 만들어 `backup/…` 갈래에 보관 — 사용자의 작업 폴더와 stage 상태를 전혀 건드리지 않음
- **받아오기 충돌 시 자동 `merge --abort`** — 저장소를 "합치다 만" 상태로 두지 않음. 해결은 사용자가 원할 때만 시작
- 충돌 해결 저장 시 충돌 기호가 남아 있으면 거절

### 4.2 Git 출력을 정확하게 해석하기
- `git status --porcelain=v1 -z`: NUL 구분으로 공백·한글 파일명 안전 처리, 이름 바뀐 파일의 원래 이름까지 처리
- `git log` 를 제어 문자(`%x1f`, `%x1e`)로 구분해 메시지에 어떤 글자가 있어도 안전하게 해석, `--decorate=full` 로 내 갈래·온라인 갈래·태그 구분
- unified diff 해석(줄 번호 추적), 충돌 기호 해석(기본·diff3 형식, Windows 줄바꿈 보존)
- Windows 에서 git 을 실행할 때 콘솔 창이 깜빡이지 않게(`CREATE_NO_WINDOW`), 터미널 비밀번호 입력 대기로 앱이 멈추지 않게(`GIT_TERMINAL_PROMPT=0`)

### 4.3 그래프 레인 배치 알고리즘
- 최신 저장 지점부터 내려가며 "각 레인이 다음에 기다리는 저장 지점"을 추적하고, 부모에게 레인을 넘겨주는 방식으로 갈래가 겹치지 않게 배치
- 간선마다 지나갈 레인(via lane)을 기록해, 출발 직후 꺾고 도착 직전에 꺾는 곡선으로 합침·갈라짐을 표현
- 그래프 모양에서 "합치기 / 갈라짐 / 몇 번째 저장 지점" 같은 설명을 계산해 마우스를 올리면 보여줌

### 4.4 보안
- 비밀 파일 판별(이름 패턴), AI 서버에 보내기 전 키·비밀번호 패턴 가리기
- 저장소 밖 경로(`..`, 절대 경로) 차단, 사용자 입력이 git 옵션으로 해석되지 않게 `--` 구분과 값 검증 (해시는 16진수만, 주소는 `https://`·`git@` 만)
- Tauri 권한 시스템으로 화면이 쓸 수 있는 기능을 최소화(폴더 선택, 링크 열기)

### 4.5 구조 설계
- Rust 는 **일반 함수(테스트 가능)** 와 **비동기 명령(화면용)** 을 분리 — 명령은 `spawn_blocking` 으로 실행해 push 처럼 오래 걸리는 작업 중에도 창이 멈추지 않음
- 충돌 해결 화면은 **백엔드 인터페이스(`ResolverBackend`)** 로 분리해, 실제 저장소(git 명령)와 웹 데모(준비된 데이터)가 같은 화면을 공유
- AI 서버: zod 스키마로 요청 검사 + 구조화 출력(JSON 스키마 강제), 안전 분류기 거절 시 서버 측 대체 모델, 에러를 쉬운 말로 변환

## 5. 문제 해결 사례

| 문제 | 원인 | 해결 |
|---|---|---|
| `.gitignore` 가 생기기 전 시점으로 되돌리면 **`.env` 가 지워짐** | 새 파일 정리(`git clean`)를 되돌린 **뒤**에 해서, 그 시점엔 `.env` 가 무시 대상이 아니었음 | 정리를 되돌리기 **전**에 해서 지금의 `.gitignore` 기준으로 처리. 이 상황을 테스트로 고정 |
| 스냅샷 1번에 **1.1초**, 쌓일수록 느려짐 | 찍을 때마다 기존 스냅샷 목록 전체를 다시 계산 (Windows 는 git 실행 1번에 수십 ms) | 직전 스냅샷 하나만 확인하도록 변경 → **0.3초**, 쌓여도 일정 |
| Linux CI 에서만 스냅샷 테스트 실패 (로컬에서도 3번 중 1번) | 초 단위 정렬이라 같은 1초 안에 찍은 스냅샷 순서가 해시 값에 따라 뒤섞임 | 이름을 밀리초 시각(자릿수 고정)으로 만들어 이름 순 정렬. 연속 5번 찍기 테스트 추가 |
| CI 에서 서버 `npm ci` 실패 | CI 의 Node 22(npm 10)가 npm 11 로 만든 lockfile 을 거부 | 로컬에서 npm 10 으로 재현해 원인 확인 → CI·배포를 개발 환경과 같은 Node 24 로 통일 |
| 1인 개발이라 실제 앱 클릭 테스트가 어려움 | 데스크톱 앱(Tauri)은 일반 브라우저 자동화가 안 됨 | WebView2 원격 디버깅으로 실제 앱을 자동 조작. 폴더 선택 창 대신 "실행 인자로 폴더 열기" 기능을 만들어 테스트에 활용 |
| 테스트가 개발자 PC 의 Git 설정을 바꿀 위험 | 이름·이메일 설정은 PC 전체 설정을 바꿈 | 테스트 앱에만 임시 설정 파일(`GIT_CONFIG_GLOBAL`) 사용, GitHub 로그인 창은 `GCM_INTERACTIVE=never` 로 차단 |
| Windows 에서만 테스트 문자열 비교 실패 | PC 의 `core.autocrlf` 설정으로 줄바꿈이 CRLF 로 바뀜 | 테스트 저장소마다 `autocrlf=false` 고정, 파서는 CRLF 를 보존하도록 별도 테스트 |

## 8. 개발 과정

1. **기획**: 문제 정의, 대상 사용자, 경쟁 서비스 분석, 가설과 검증 계획 작성
2. **클릭형 프로토타입**: React 로 저장 → 비밀 정보 경고 → 되돌리기 흐름을 만들고 사용자 테스트용 과제·기록 기능 추가
3. **디자인 개편**: GitKraken·Warp 를 참고해 다크 모드, Git 그래프, 터미널 블록, 폴더 트리, 크기 조절 가능한 패널로 재구성
4. **기술 선택**: 웹/데스크톱, 여러 프레임워크·언어 비교 후 Tauri(Rust) 결정 — [기술-선택.md](기술-선택.md)
5. **실제 Git 연결**: status → 그래프(log) → 커밋 → 올리기 → 받아오기 → 충돌 해결 → 되돌리기 → diff 순서로 확장
6. **AI 서버**: NestJS 로 설명·메시지 추천·충돌 설명 구현 (현재는 기능 스위치로 비활성화)
7. **처음 쓰는 사람을 위한 기능**: 시작 화면, Git 시작, 가져오기, GitHub 연결, 이름·이메일, 무시 목록·큰 파일 도우미
8. **CI**: 3개 OS 자동 테스트 — 도입 직후 실제 버그(스냅샷 순서)를 발견
9. **시간 기록(스냅샷)**: 측정 → 성능 개선 → 자동 스냅샷 설계로 진행 중

## 10. 돌아보며

- **"안전"이 기능보다 먼저**였습니다. 비개발자용 Git 도구에서 가장 큰 실패는 사용자 코드를 잃는 것이라, 되돌리기·충돌·스냅샷 모두 "실패해도 원래대로"를 먼저 설계하고 테스트로 고정했습니다.
- **측정하고 나서 결정**했습니다. 자동 스냅샷은 바로 만들지 않고, 수동 버전으로 시간·디스크를 측정한 뒤 그 수치(예: 바이너리 파일은 1번에 5MB 증가)를 근거로 자동 규칙을 설계했습니다.
- **CI 는 바로 값을 했습니다.** 도입하자마자 로컬에서는 가끔만 보이던 정렬 버그를 Linux 에서 잡았습니다.
- Rust 는 처음이었지만, Rust 는 "git 실행과 해석"에 집중시키고 화면 로직은 TypeScript 에 두는 구조로 학습 부담을 나누었습니다.
